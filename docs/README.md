## 1. Назначение

Приложение — личный финансовый план по выплатам зарплаты. Каждая выплата (аванс или зарплата) — это **период**. Для каждого периода приложение:

- берёт доход на руки и отпускные;
- вычитает плановые расходы по категориям и платежи по рассрочкам;
- гасит кредитки так, чтобы уложиться в льготный период;
- распределяет остаток по целям накоплений с учётом их сроков;
- показывает, сколько денег осталось свободными или сколько не хватает.

**Разделы (вкладки):** *Обзор*, *Доходы*, *Категории*, *Накопления*, *Кредиты*, *Рассрочки*, *Настройки*.

### 2.1. Порядок запуска

1. `boot()` проверяет сессию (`ensureSignedIn`). Нет сессии — показывается форма входа; после успешного входа запуск продолжается.
2. `loadStateFromDB()` вызывает `get_full_state`. Если ответ пустой или произошла ошибка, берётся встроенный план по умолчанию (`DEFAULT_STATE`). Недостающие поля заполняются значениями по умолчанию (например, `locked = false` у периодов, пустой список подцелей у целей).
3. Затем вызывается `get_debts_state`.
   - **Успех** — данные нормализуются (`normalizeDebts`), флаг `debtsStorageOk = true`.
   - **Ошибка** (например, не выполнен `debts.sql`) — долги пустые, `debtsStorageOk = false`. На вкладках «Кредиты» и «Рассрочки» показывается красное предупреждение, долги в базу *не отправляются*. Так незагруженные данные не затираются пустыми.
4. `render()` отрисовывает активную вкладку.

### 2.2. Сохранение

- Текстовые и числовые поля фиксируют значение при потере фокуса или по Enter. Списки и флажки — сразу при изменении.
- После любого изменения вызывается `scheduleSave()`. Она сразу перерисовывает экран и через 500 мс запускает `doPublish()`. Частые правки подряд объединяются в одно сохранение.
- `doPublish()`:
  1. отправляет в `save_full_state` копию состояния *без* ключа `debts`;
  2. если `debtsStorageOk`, отправляет `state.debts` в `save_debts_state`.
- `save_debts_state` полностью заменяет долги текущего пользователя: удаляет его строки и вставляет заново из JSON.

| Статус в шапке | Когда показывается |
|----------------|--------------------|
| Сохранение… | Изменение ожидает отправки (500 мс) или отправляется. |
| Сохранено | Обе функции сохранения завершились без ошибки. |
| Ошибка сохранения | Любая из функций вернула ошибку. Подробности — в консоли браузера. |

> **📝 Примечание**  
> Не сохраняются: черновик формы «Новый период», черновик формы «Новая покупка», окно перераспределения остатка, раскрытие списка прошедших выплат. Раздел `ui` (активная вкладка, раскрытые карточки, выбранный год) передаётся в `save_full_state`; сохранится ли он, зависит от этой функции.

### 2.3. Что происходит при каждой отрисовке

Перед отрисовкой `render()` приводит данные к единому виду. Если что-то изменилось, запускается сохранение.

1. `sortSubgoalsByDeadline` — подцели каждой цели сортируются по сроку: ранние выше, без срока в конце.
2. `syncIncome2026` — суммы аванса и зарплаты за месяцы 2026 года копируются в «Доходы за 2026».
3. `sortInstallmentPayments` — платежи каждой рассрочки сортируются по дате.
4. `ensurePastPeriodsLocked` — прошедшие периоды фиксируются (см. п. 5.11).
5. `simulate()` — полный расчёт всех периодов (см. п. 5.9).
6. Отрисовка активной вкладки и окна перераспределения, если оно открыто.

Раз в минуту приложение проверяет, не сменилась ли дата. Если сменилась и курсор не стоит в поле ввода, экран перерисовывается: обновляется дата в шапке и деление выплат на прошедшие и будущие.

## 3. Модель данных

Все даты хранятся строками `ГГГГ-ММ-ДД`. Суммы — рубли; при вводе округляются до целого (`parseNum`). «Сегодня» — дата на устройстве пользователя (`todayISO`).

### 3.1. Основное состояние: `get_full_state` / `save_full_state`

| Ключ | Содержимое | Где вводится | Для чего используется |
|------|-----------|--------------|----------------------|
| `ui` | `tab`, `openPeriods`, `selectedYear`, `openWdYears` | Интерфейс | Положение пользователя в приложении. |
| `oklad.history` | `effectiveFrom` (дата начала), `amount` (оклад gross) | Настройки → Оклад | Подсказка «по формуле» для аванса и зарплаты, индексация при расчёте отпускных, процент в Категориях. |
| `ndfl.brackets` | `upTo` (верхняя граница годового дохода, пусто — без границы), `rate` (доля, 0.13 = 13%) | Настройки → Налог | Расчёт НДФЛ в подсказке, оценка «на руки». |
| `income2026` | Доход на руки за каждый месяц 2026 года | Настройки → Доходы за 2026 | Средний заработок для отпускных. |
| `sickLeaves` | `id`, `start`, `end`, `note` | Настройки → Больничные | Уменьшение коэффициента 29,3 в расчёте отпускных. |
| `vacations` | `id`, `start`, `end`, `note`, `manualPay` (отпускные к выплате) | Настройки → Отпуска | Доход периода (через привязку к периоду), расчёт по формуле для сравнения. |
| `categories` | `id`, `name`, `amount`, `items` (статьи: `name`, `amount`, `season`), `season` (`from`, `to` в формате `ММ-ДД`) | Категории | Плановые расходы каждого периода. |
| `goals` | `id`, `name`, `priority`, `target`, `deadline`, `startingBalance`, `completed`, `subgoals` (`id`, `name`, `target`, `deadline`), `withdrawals` (`date`, `amount`, `note`, `label`) | Накопления | Цели и этапы, траты из копилок, переводы между копилками. |
| `periods` | `id`, `date` (дата выплаты), `label` (ДД.ММ), `type` (`avans` / `zp`), `half` (`first` / `second`), `monthRef` (`y`, `m` — за какой месяц), `calc` (`auto` / `manual`), `incomeActual` (доход на руки), `assignedVacations` (`id`, `share`), `locked`, `note` | Доходы, Настройки → Годы | Основа всего расчёта. |
| `categoryOverrides` | ид периода → ид категории → сумма | Доходы → Расходы по категориям | Замена плановой суммы категории в конкретном периоде. |
| `savingsOverrides` | ид периода → ид цели → сумма | Доходы → Распределение по копилкам; автоматически при фиксации | Ручные или зафиксированные суммы в копилки. |
| `meta.holidays` | Даты праздников | Настройки → Производственный календарь | Подсчёт рабочих дней. |

**Особенности полей:**
- `withdrawals.amount` больше нуля — трата из копилки. Меньше нуля — пополнение переводом из другой копилки. В интерфейсе они показаны в разных блоках, сумма всегда положительная.
- Название траты записывается одновременно в `note` и `label`. При чтении берётся `note`, а если оно пустое — `label`.
- `calc = manual` означает ручной период: доход вводится только вручную, период можно удалить, у него можно менять тип и месяц.

### 3.2. Кредитки и рассрочки: `get_debts_state` / `save_debts_state`

## 6. Когда что пересчитывается

| Событие | Что происходит |
|---------|---------------|
| Открытие страницы | Вход, загрузка обоих состояний, нормализация, фиксация прошедших периодов, полный расчёт. |
| Правка любого поля | Запись в состояние → полный пересчёт и перерисовка → сохранение через 500 мс. |
| Смена вкладки, года, раскрытие карточки | Перерисовка с полным пересчётом (без изменения данных, кроме фиксации прошедших периодов). |
| Смена даты на устройстве | В течение минуты — перерисовка: новые прошедшие периоды фиксируются, дата в шапке обновляется. |
| Флажок «цель выполнена» | Сохранение и, при остатке в копилке, окно перераспределения. |
| Изменение параметров рассрочки | График пересоздаётся. |
| Удаление кредитки | Удаляются её операции и все ручные погашения по ней. |
| Удаление года | Удаляются периоды года, их суммы в копилки и замены расходов. |

## 8. Ограничения и особенности

> **📝 Примечание**  
> Ниже — особенности текущей версии, которые важно учитывать при работе и доработке.

1. **Доход периода не пересчитывается из оклада.** В расчёте всегда участвует «Доход на руки (факт)». Сумма «по формуле» — только подсказка.

2. **Новый год создаётся с доходом gross.** `generateYearPeriods` записывает в «Доход на руки» сумму по формуле *до* вычета НДФЛ. После добавления года суммы нужно поправить.

3. **Привязка отпусков к периодам не редактируется в интерфейсе.** Отпускные попадают в доход только через `assignedVacations`. Новые отпуска, добавленные в Настройках, в доход периодов не попадают.

4. **Правка одной копилки переводит весь период на ручные суммы.** Цели, для которых сумма не вписана, в этом периоде получают 0.

5. **Прогресс целей — на конец плана**, а не на сегодня. Текущее состояние показывает строка «на счету сейчас».

6. **Прошедшие выплаты:** в списке прошедшей считается выплата с датой *не позже* сегодняшней, а фиксируется она только со следующего дня.

7. **Праздники общие для всех лет.** По умолчанию заданы праздники 2027 года без переносов.

8. **Процент в Категориях** считается от последней записи в списке окладов (по порядку в списке, а не по дате).

9. **Кредитки:**
   - прогноз будущих свободных денег не учитывает, что их делят несколько карт;
   - проценты и штрафы за просрочку не рассчитываются;
   - лимит не ограничивает траты — только выводится предупреждение.

10. **Рассрочки:** при изменении суммы, числа частей, даты или периодичности ручные правки платежей теряются.

11. **Даты по умолчанию** при добавлении: трата из копилки — 05.01.2027; повышение оклада — 01.06.2027; отпуск — 01.06–07.06.2027; срок новой цели — 31.12.2027. Текст статуса «Не достигается в 2027 году» не зависит от лет плана.

12. **Одновременная работа с двух устройств:** каждое сохранение перезаписывает данные целиком, побеждает последнее.

13. **«Сегодня»** определяется по часам и часовому поясу устройства.
